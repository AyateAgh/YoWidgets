# YoWidgets — отключение и полное удаление

19 октября 2026 года. Контракт реализован в scripts/install.ps1, scripts/uninstall.ps1 и Cleanup.cs. Проверки частичного удаления, чужих файлов, junction и заблокированных служебных файлов перечислены в [verification.md](verification.md). Предварительные пункты о дополнительных backend/identity применяются только при их фактическом подключении.

## Операции для пользователя

**«Отключить всё»** — одно нажатие в приложении или трее. Останавливает виджеты, запросы, периодические таймеры, анимации и необязательные подписки; снимает desktop-привязку собственных окон, отключает автозапуск. Настройки и установленные файлы сохраняются. Для контроля завершения остаётся только окно управления/минимальный tray. Восстановление работы не включает автозапуск и приватные интеграции заново без явно выбранной настройки. Простое скрытие и Snooze — другие, подписанные действия, не выдаваемые за отключение.

**«Удалить полностью»** — одна конечная кнопка на специальной странице с заранее видимым списком удаляемых данных и предупреждением о потере сохранённой конфигурации. Не требует ручной последовательности PowerShell-команд. Убирает все созданные приложением ресурсы текущего пользователя, включая внешние файлы Sparse Package. Обычное закрытие окна и обычный выход не удаляют сохранённые данные.

Задача удаления — вернуть окружение без активного YoWidgets и его принадлежащих ему артефактов. Это не обещание стирания системных журналов Windows, Prefetch, истории установок или резервных копий, которыми управляет ОС. Не очищать их ради заявления «никаких следов».

## Что принадлежит приложению

| Ресурс | Создание | Удаление / обратная операция |
|---|---|---|
| Окна, привязка DesktopHost, GPU-ресурсы | Только собственные HWND/устройства | Закрыть собственные поверхности и освободить ресурсы; не менять HWND/стили Explorer и не перезапускать его. |
| Процесс и helper | Исполняемые файлы своей установки | Завершить только проверенные экземпляры с совпадающими путём, PID и временем старта; не завершать процессы только по имени. Helper заканчивает работу после проверки. |
| Автозапуск | Один выбранный per-user механизм, по явному включению | Удалить только запись/ярлык/StartupTask YoWidgets с проверкой identity и текущего содержимого. Не плодить Run + task + Startup folder одновременно. |
| Установленные бинарники/assets | Отдельный `%LOCALAPPDATA%\Programs\YoWidgets`, манифест установленного состава | Удалить собственные установленные файлы после завершения приложения. Не использовать рабочую папку с исходниками и examples как install-root. |
| Конфигурация, кеши, локальные копии фото, ключи ИИ | Отдельный app data root и при необходимости собственный package data root | Удалить конфигурацию, локальные копии, кеши, DPAPI blobs и принадлежащие приложению записи Credential Manager, если такой backend будет выбран. Исходные изображения не удалять. |
| Package identity | Sparse Package текущего пользователя | RemovePackageAsync/Remove-AppxPackage по точной проверенной identity. Не AllUsers, не wildcard-поиск с массовым удалением. Внешний install-root очищать отдельно. |
| Разрешение notification listener | Системный consent для identity | Отписаться и удалить package registration при полном uninstall. Не править приватные consent-ключи реестра. Метаданные разрешений, оставленные Windows, не выдавать за собственный файл, который можно безопасно стереть вручную. |
| Ярлыки/запись деинсталляции | Только свои per-user пути и ключи | Снять собственные ссылки/запись. Не изменять чужие пункты Start/Startup. |
| Хоткей и IPC | RegisterHotKey, собственные named pipe/mutex | UnregisterHotKey и освобождение объектов/дескрипторов. Никаких постоянных keyboard hooks. |
| Dev identity и инструменты сборки | Отдельный dev-журнал | Парная dev-unregister команда и cleanup только собственных созданных артефактов. Не удалять исходники, examples и заранее установленные инструменты. |
| Dev-сертификат, если действительно необходим | Только явная операция, точный thumbprint и запись о прежнем наличии | Удалить только сертификат, который создан и добавлен исключительно этим проектом и не был ранее установлен/общим. Не менять LocalMachine Root и не удалять чужие сертификаты. |

Имена пакета, ключей и точные подкаталоги фиксируются до первого установочного действия в manifest ресурсов. Если регистрация уведомлений отключена, identity не устанавливается «на всякий случай». Общие .NET, Windows App SDK и другие системные runtime в cleanup не входят. Отдельно учитываются downloads/SDK, полученные при разработке: они не становятся частью обычного uninstall установленной утилиты.

## Журнал и защита границ

Перед каждым постоянным изменением сохраняется атомарная запись: версия схемы, installation id, текущий пользователь, тип ресурса, разрешённый идентификатор, существовал ли ранее, прежнее значение для изменяемой настройки, ожидаемое новое значение и стадия операции. Стадии: `prepared → applied → reverted`; ошибки и незавершённые операции сохраняются до проверки восстановления. Журнал не содержит ключей ИИ, содержимого уведомлений или снимков экрана.

Журнал — данные, а не список исполняемых команд и не источник произвольных путей удаления. Очиститель имеет собственный ограниченный перечень допустимых типов/корней/identity. Перед рекурсивным удалением проверяется разрешённый абсолютный путь, владелец установки, отсутствие опасного корня/родителя и reparse-point обходов. Junction/symlink не обходится рекурсивно. Нельзя превращать строку из настроек/журнала в PowerShell/cmd-код. Для файлов применяются нативные файловые API или PowerShell `-LiteralPath`, без передачи найденных путей в другой shell.

Существовавшие ранее ресурсы не присваиваются приложению и не удаляются. При повреждённом/отсутствующем журнале очищаются только независимо подтверждённые собственные ресурсы; сомнительные элементы показываются как остатки. Исходники проекта, папка examples, пользовательские фото, Windhawk и его конфигурация не затрагиваются.

## Системные параметры и предел обратимости

Приложение не меняет обои: IDesktopWallpaper используется для чтения. Программа также не меняет DND/радио Wi-Fi автоматически, не регистрирует службу/драйвер, не отключает защиту, не меняет глобальный ExecutionPolicy и не включает Developer Mode скрыто. Это сокращает перечень постоянных изменений.

Громкость, mute и яркость — явные действия пользователя. При обычном закрытии/выходе они сохраняются. На странице удаления есть явно подписанный вариант «Также отменить изменения громкости и яркости YoWidgets». Перед первой записью сохраняется исходное значение, идентификатор устройства и последнее успешно установленное значение. Восстановление допускается только для того же устройства, если текущее состояние совпадает с последним собственным значением, с учётом точности устройства; при внешнем изменении не перезаписывать его молча. Проверка выполняется непосредственно перед восстановлением, доступные callbacks используются для обнаружения внешних изменений. Не заявлять атомарную транзакцию там, где API её не предоставляет.

При конфликте показывается, что именно не откатилось и почему; пользователь может явно выбрать восстановление исходного значения. Безопасная автоматическая очистка не должна отменять более поздние действия человека или других приложений. Нельзя одновременно обещать безусловное возвращение любого старого состояния и сохранение последующих чужих изменений.

Команды воспроизведения, уже выполненные сетевые запросы, история у внешнего ИИ-провайдера и действия, выполненные пользователем в штатных настройках Windows, не являются автоматически обратимыми артефактами установки. Uninstall не переключает треки обратно, не отменяет сторонние платежи и не пытается стереть историю чужих приложений. Notification feed не удаляет оригиналы уведомлений и не требует восстановления их истории.

## Порядок полного удаления

1. Построить и показать перечень фактически принадлежащих приложению ресурсов, а не универсальный рекламный список.
2. После конечного действия пользователя заблокировать повторный запуск задач, отменить запросы и сохранить состояние удаления. Исключить два параллельных очистителя.
3. При явно выбранном откате системных параметров выполнить проверку конфликтов и доступности устройств.
4. Отключить автозапуск/интеграции, освободить hotkey/IPC, убрать собственные окна и desktop-привязку.
5. Завершить основной процесс. Отдельный небольшой helper, запущенный скрыто, продолжает очистку. Взаимодействие привязано к конкретной установке, не к произвольным аргументам-путям.
6. Удалить identity текущего пользователя и проверить отсутствие регистрации; отдельно убрать известные внешние файлы, data roots, секреты и ярлыки. Не удалять рабочий каталог исходников.
7. Проверить результат независимыми запросами. Только после проверки убрать собственную uninstall-запись. Если шаг не завершён — сохранить возможность повторить cleanup и точный список остатков.
8. Helper завершает работу; его временная копия удаляется принадлежащим приложению проверенным механизмом. Если файл заблокирован и немедленное удаление невозможно, сообщить об этом честно, не требовать выключения защиты или принудительного убийства чужого процесса. Не заявлять «полностью удалено» при оставшемся helper/регистрации/файлах.

Удаление идемпотентно: повторная операция после сбоя не повреждает окружение и не считает уже отсутствующие собственные ресурсы ошибкой. Отмена возможна до начала конечной операции, но удаление локальных данных не представляется полностью обратимым после выполнения.

## Условия приёмки

- Снять baseline своих предполагаемых путей/identity/автозапуска до установки, затем повторить проверку после полного удаления.
- Проверить выключение всех виджетов одной кнопкой, отсутствие запросов/тиков/анимаций и сохранность конфигурации.
- Проверить uninstall после работы каждого модуля, после аварии, при запущенной второй копии, заблокированном файле и повреждённом журнале.
- Проверить исходное существование совпадающего ресурса, посторонний файл и junction: чужие данные не удаляются, ошибка владения видна.
- Проверить условный откат громкости/яркости и конфликт с внешним изменением, отсутствие устройства и смену default endpoint.
- После uninstall не осталось процесса/окон, package identity, автозапуска, записей секретов, созданных ярлыков, собственных runtime-файлов/кешей; приложение не появляется после входа в систему. Недоступность перезагрузки/повторного входа обозначается как непроверенный тест.
- Dev-register/dev-unregister проверяются отдельным циклом; удаление identity не выдаётся за удаление внешних файлов.
- Проверить, что Windhawk, исходные фото, examples, чужие пакеты и общие runtime не изменились.
- Текст результата строится из реальных проверок: «Удалено», «Удалено частично: …», «Не удалось: …», без ложного успешного статуса.

Источник по identity/unregister: [Microsoft: packaging with external location](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/grant-identity-to-nonpackaged-apps). Windows управляет удалением регистрации пакета; внешние файлы и собственные интеграции остаются ответственностью YoWidgets.
