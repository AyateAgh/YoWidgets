# YoWidgets — предложение для согласования

Дата: 19 октября 2026 года. Редакция 3 после проверки рендеринга, обоев, package identity и удаления. Статус: проект решения; приложение ещё не реализовано. Проверены исходники и документация API, а не готовая работающая программа. Подробности — в [technical-review.md](technical-review.md), контракт отключения и удаления — в [cleanup-contract.md](cleanup-contract.md).

## Задача

Лёгкое приложение для Windows 11 с минималистичным интерфейсом управления и виджетами с настоящим шейдерным преломлением по мотивам двух локальных видео и MacShell. Пользователь уточнил: нужны виджеты и окно управления; затем добавил Focus/Snooze, уведомления, компактные быстрые настройки, раскрытие плеера и необязательный ИИ-виджет. Полная оболочка, Dock, верхняя панель и замена экрана блокировки в объём не входят.

Референсы: `examples/LiquidGlassAppleWidgets.mp4` (38 секунд), `examples/LiquidMusicPlayer.mp4` (59 секунд), https://github.com/0-ss/MacShell. В первом ролике преимущественно показан Control Center; во втором есть настольные виджеты и музыкальный плеер. Настольный плеер включён; системный экран блокировки Windows не подменяется.

## Рекомендуемая архитектура

Нативное C#/WPF-приложение со значком в системном трее; WPF — предварительный выбор для управления и содержимого. Рендерер `GlassSurface` отделён от данных и логики окон. До закрепления стека обязателен работающий образец преломления, его замер и проверка совместимости с настольным слоем. Первым проверяется HLSL/ShaderEffect; если его ограничения мешают обязательному эффекту, рендерер переносится в нативный GPU-host. Упрощённая полупрозрачная карточка не считается выполнением требования Liquid Glass.

Окно управления закрывается независимо от виджетов. Каждый виджет — собственное окно/поверхность без кнопки на панели задач. Общие службы данных, настройки, изображения и таймеры разделяются между экземплярами. Модуль `DesktopHost` отвечает за положение относительно рабочего стола и Win + D; `DisplayGeometry` — за мониторы, DPI и координаты.

Проверка WPF-шейдера ограничивается одним компактным образцом, а не серией обходов ограничений PS 3.0. Предварительное размытие — отдельный кешируемый проход. Если компилятор/целевое устройство не поддерживают нужный алгоритм, качество или время кадра не проходят критерии, основной путь — Direct3D 11 + DirectComposition/SwapChain. Нативный вариант обязан учитывать airspace: обычный дочерний HWND через HwndHost нельзя просто накрыть WPF-контролами и считать смешивание решённым. Допустимы проверенная общая поверхность или целиком нативная сцена виджета; WPF остаётся окном управления. Никакого покадрового CPU-readback ради соединения технологий. PS 3.0 имеет ограничения, но 512 инструкций — гарантируемая базовая ёмкость стандарта, а не универсальный максимум; управление потоком стандартом поддерживается. Фактический бюджет определяется компиляцией и поддержкой устройства/WPF.

Варианты: WinUI 3 удобен штатными материалами Windows, но сам по себе также не предоставляет эффект MacShell; Tauri добавляет WebView2 и межпроцессное взаимодействие. WPF выбран предварительно как прямой путь к нативным окнам и Windows API. Это инженерный выбор, а не обещание заранее измеренного расхода памяти. Для ленты уведомлений предусматривается поставка с package identity, capability `userNotificationListener` и системным запросом разрешения; работоспособность упакованной сборки проверяется отдельно от обычного EXE.

При разработке notification-модуля — Sparse Package с внешним расположением бинарников. Локальная регистрация манифеста через `Add-AppxPackage -Register -Path <manifest> -ExternalLocation <absolute-build-directory>` проверяется на текущей машине; Developer Mode и доверие сертификатам не меняются скрыто. Для поставки — подписанный identity-only пакет, регистрация per-user с `-Path <identity.msix> -ExternalLocation <install-directory>` либо эквивалентный PackageManager API. Манифест пакета, identity EXE, Publisher/ApplicationId и assets согласованы. Регистрация выполняется при необходимости, не при каждой пересборке кода. После запуска проверяются реальная identity и отдельное разрешение listener; одна регистрация не даёт автоматического доступа ко всем уведомлениям. Парные операции unregister/cleanup обязательны. Никаких глобальных изменений ExecutionPolicy, доверия корневым сертификатам или регистрации для всех пользователей.

На компьютере обнаружены .NET Desktop Runtime 8.0.22 и NVIDIA RTX 3050 Laptop. .NET SDK не обнаружен; для сборки понадобится локально установить SDK в папку инструментов проекта, без замены системного runtime. Версию целевой платформы определить по актуальной поддержке и проверке сборки.

| Focus / Snooze | Локальная пауза обновлений приложения; собственный Pomodoro с заданным временем окончания; переход к штатным настройкам уведомлений Windows. Состояние системного Focus показывается только при доступности соответствующего API; это не индикатор DND. |
| Уведомления | Необязательная стеклянная лента системных toast-уведомлений после отдельного разрешения Windows. Отказ/отзыв доступа и пустая лента — полноценные состояния. Snooze прекращает показы только собственных карточек. |

| ИИ | Необязательная строка запроса и компактный ответ, ручная отправка, отмена, таймаут и состояние отсутствующего провайдера. По умолчанию выключен; без фоновой модели. Подключение провайдера настраивается явно; ключ защищается Windows DPAPI, не попадает в логи. Уведомления, обои и экран в запрос автоматически не включаются. |

Медиаданные и команды проходят через Windows GlobalSystemMediaTransportControls. Возможности определяет источник: неподдерживаемые команды недоступны и объяснены. Нет активного источника — отображается инструкция открыть совместимый плеер. Ошибки команд показаны пользователю; интерфейс не симулирует успешное переключение.

Плеер имеет компактное состояние высотой примерно 90 DIP и раскрытое от 320 DIP с крупной обложкой/текстом. Размер контейнера, скругление и содержимое меняются синхронно за 180–240 мс. Проверяются повторные быстрые переключения, края экрана, переход между DPI и клавиатурный фокус. При уменьшении движения — мгновенная смена. При Snooze — без переходов. Текст песни доступен при наличии данных сервиса.

ИИ-сводка дня может использовать уже полученную погоду и текущую дату. События календаря не выдумываются: подключения к календарным аккаунтам в этом проекте нет. Собственный Focus/Pomodoro и системный Do Not Disturb — разные сущности. `ToastNotificationManager.History` и notification listener не используются как датчик DND. Управление системной Focus-сессией не обещается: методы запуска/остановки Microsoft относит к Limited Access Feature.

Лента не подменяет всю систему уведомлений: приложения со своими несистемными всплывающими окнами в неё могут не попасть. Listener читает/удаляет уведомления, но не является фильтром до их системного показа. Локальное скрытие карточки не удаляет исходное уведомление из Windows. Автоматическое удаление системной истории и фоновые задачи после выхода приложения не добавляются.

## Управление

Главный экран — каталог типов с реальными миниатюрами, переключателями и количеством экземпляров. Необязательные интеграции явно обозначены. Боковая навигация: «Виджеты», «Оформление», «Настройки». Общая кнопка временно скрывает или возвращает включённые виджеты, сохраняя индивидуальные настройки.

Настройка экземпляра: размер S/M/L, прозрачность, светлый/тёмный/системный режим, экран размещения, положение. Режим редактирования позволяет перетаскивать виджеты с привязкой; клавиатурное перемещение и сброс положения дают альтернативу мыши. В обычном режиме декоративные части пропускают нажатия, элементы плеера остаются доступны. По умолчанию виджеты располагаются позади обычных окон; режим поверх окон включается явно.

`Topmost=false` недостаточно для настольного поведения. `DesktopHost` обязан выдерживать Win + D, сворачивание/восстановление окон, перезапуск Explorer и смену виртуального рабочего стола. Привязка к WorkerW/Progman — кандидат для проверки, а не стабильный контракт Windows; при ошибке приложение убирает собственные поверхности, показывает возможность повторного подключения и не перезапускает Explorer. Перехват `WM_WINDOWPOSCHANGING` сам по себе не считается решением Win + D.

Манифест задаёт `PerMonitorV2` до создания окон. Координаты интерфейса хранятся в DIP, GPU-текстуры и выборка фона рассчитываются в физических пикселях текущего монитора. При `WM_DPICHANGED` пересчитываются размер, позиция и выборка обоев. Для `SetParent` отдельно проверяются DPI-контексты: этот API может сбрасывать DPI-awareness дочернего процесса при несовпадении контекстов.

После перезапуска восстанавливаются включение, размеры, положение и оформление. При отключении монитора виджеты возвращаются в видимую рабочую область. Автозапуск — отдельный выключенный по умолчанию переключатель. В трее доступны открыть управление, показать/скрыть виджеты, редактировать расположение и полностью выйти.

Добавлены отдельные действия «Отключить всё» и «Удалить полностью». Первое за одно нажатие прекращает работу виджетов, снимает привязку собственных окон к рабочему столу, отключает автозапуск и необязательные интеграции, сохраняя конфигурацию для возврата. Второе запускается одной конечной кнопкой на странице удаления с заранее видимым перечнем удаляемых данных: убирает установку, identity, созданные регистрации, локальные данные/ключи/копии изображений и проверяет результат. Подробный перечень, порядок, восстановление после сбоя и границы операции определены в [cleanup-contract.md](cleanup-contract.md). Изменение исходных фото, папки examples, Windhawk или других программ в удаление не входит.

## Дизайн

Предметный образ: небольшая коллекция стеклянных приборов над рабочим столом. Узкая спокойная боковая панель, свободная сетка превью и компактные настройки. Фирменный элемент — объёмное преломление под скруглённой линзой с изменяющимся бликом. Контент и подписи сохраняют читаемость; постоянное декоративное движение не требуется для живого стекла.

- Палитра: фон #11151D, поверхность #202735, основной текст #F4F7FB, вторичный #B4C0D1, акцент #78ADFF, ошибка #FFB4AE. Светлая тема использует те же семантические роли с контрастным тёмным текстом.
- Шрифты: Segoe UI Variable Display для заголовков и часов, Segoe UI Variable Text для интерфейса; локальные системные шрифты без загрузок из сети.
- Радиусы: 24 px у виджетов, 16 px у панелей, 10 px у полей; контролы с отчётливым фокусом и состоянием нажатия.
- Стекло: общий GPU-шейдер на основе физики MacShell — SDF скруглённой поверхности, нормаль выпуклого края, смещение выборки по преломлению, слабая RGB-дисперсия, размытие предварительного прохода, линзовое увеличение, оттенок и направленный блик. Непосредственно текст и иконки не искажаются. Параметры «Преломление», «Размытие», «Оттенок» работают независимо.
- Источник фона для настольных виджетов — системные обои с правильным монитором, режимом Fill/Fit/Stretch/Tile/Center/Span и координатами. Это соответствует настольным виджетам MacShell. При перемещении и смене обоев выборка обновляется; всплывающие окна поверх посторонних программ и сторонние видеообои не выдаются за ту же подтверждённую возможность. Без доказанного доступа к подходящему живому фону они получают явно обозначенный другой режим, а не подставленные обои под видом захвата экрана.
- Доступ к обоям — COM `IDesktopWallpaper`: GetMonitorDevicePathCount/GetMonitorDevicePathAt, GetMonitorRECT, GetWallpaper(monitorId), GetPosition и GetBackgroundColor. GetPosition задаёт общую политику размещения, а не независимый режим каждого монитора. SPI_GETDESKWALLPAPER не является основным источником. Обрабатываются пустой путь, сплошной цвет, slideshow, отключённый монитор, ошибки COM и освобождение возвращённых строк. Span/Tile рассчитываются относительно общей геометрии рабочего стола. API не предоставляет документированный выбор обоев по ID виртуального стола: поведение на активном столе проверяется отдельно, данные перечитываются при обнаруженном изменении, недоступность обновления обозначается явно. Недокументированные COM-интерфейсы виртуальных столов ради гарантии 1:1 не добавляются.
- Матовый/Acrylic режим разрешён только как отдельно выбранная экономия или явное состояние недоступности GPU. Он не заменяет обязательную проверку шейдерного Liquid Glass. WPF-UI/AccentPolicy и двойная каёмка сами по себе это требование не выполняют. Сочетание `AllowsTransparency` и DWM-материала не используется без испытания; существование аппаратной поддержки layered-окон не доказывает совместимость конкретного эффекта.
- Анимации: короткие переходы до 180 мс, раскрытие плеера 180–240 мс при действии пользователя. Системные настройки уменьшения движения и высокого контраста учитываются.

Проверка внешнего вида обязательна для каждого виджета и каждого S/M/L: общий фон, одинаковые масштаб/оттенок и сравнение с доступными кадрами видео и компоновкой MacShell. Тестовый фон с сеткой должен зримо изгибаться у границ линзы; при отключении преломления изгиб исчезает. Видеозапись перемещения должна подтверждать обновление выборки и отсутствие запаздывающего снимка/шлейфа. Одна прозрачная карточка с красивой рамкой этот критерий не проходит. Точное пиксельное совпадение с материалом Apple на любой версии macOS не заявляется; цель — воспроизвести наблюдаемый эффект референса и проверить результат.

## Оптимизация и данные

Для настольного режима нет непрерывного захвата экрана. Текстура обоев и предварительное размытие переиспользуются; обложки и изображения декодируются под размер виджета и кешируются с ограничением памяти. GPU-эффект перерисовывается при изменении фона, геометрии и взаимодействии; нет бесконечного render-loop для неподвижного стекла. Медиаслужба использует события; таймер прогресса работает только при воспроизведении и видимом плеере. Погода обновляется редко и по запросу. Часы без секунд обновляются раз в минуту. Режим экономии снижает эффекты и отключает секунды.

Snooze отменяет незавершённые HTTP/ИИ-запросы, запрещает новые автоматические запросы и повторные попытки, отключает периодические таймеры часов/погоды/прогресса/текстов, подписки на необязательные события и все анимации. Статические карточки показывают приостановленное состояние и время последнего обновления. Для игр доступен глубокий Snooze: скрытие поверхностей, освобождение их GPU-ресурсов, сохранение только минимального обработчика трея/возврата. Ручной выход или одноразовое пробуждение по выбранному сроку возобновляет работу; пропущенные обновления не запускаются пачкой. Абсолютный ноль CPU/GPU для работающего процесса и системного композитора не обещается. Pomodoro в обычном режиме использует абсолютный deadline, а не накопление тиков.

Стартовые цели измерений: средний CPU процесса не выше 0,5% суммарной мощности за 5 минут неподвижного рабочего стола с пятью базовыми виджетами; отсутствие периодической работы приложения в глубоком Snooze; изменение памяти после 100 циклов скрытия/раскрытия без устойчивого роста. Для движения и раскрытия — целевой P95 времени кадра до 16,7 мс на 60 Гц после прогрева. Это критерии испытаний, а не уже полученные показатели. Публикуются условия, разрешение, DPI, питание, память, CPU и GPU. Нагрузка DWM учитывается отдельно, чтобы не скрывать стоимость эффекта за другим процессом.

Настройки — локальный JSON с атомарной записью и восстановлением после повреждения. Выбранные изображения — в локальной папке данных. Сеть используется для явно выбранной погоды и включённого поиска текстов; телеметрия не добавляется. Доступ к медиасессиям обрабатывает отказ и ограничения источника.

Дополнительная сеть появляется только после настройки ИИ-провайдера и ручной отправки; содержимое уведомлений по умолчанию не записывается на диск и не отправляется наружу. Приложение не меняет настройки Wi-Fi, DND, громкости или яркости при старте/возврате из Snooze: реальные системные изменения выполняются только явным действием пользователя в соответствующем контроле. Поэтому «визуальная надстройка» означает отсутствие вмешательства в оболочку, а не отсутствие действий у работающих ползунков.

Не требуются права администратора, драйвер, DLL-инъекции, замена Explorer, модификация системных файлов, отключение защит или твики реестра ради эффектов. Автозапуск — только явный выбор. Графические ошибки, потеря устройства, отказ API и перезапуск оболочки обрабатываются с ограниченным повтором; нет бесконечных циклов восстановления. Завершение приложения убирает его окна и освобождает подписки/ресурсы; выбранные пользователем уровни громкости/яркости не откатываются неожиданно. Гарантия «никогда не будет багов» не даётся: вместо неё нужны перечисленные испытания и прозрачный список подтверждённых ограничений.

Все постоянные изменения, создаваемые установкой/программой/инструментами разработки, имеют запись владения и обратную операцию до их выполнения. Полный uninstall не ограничивается закрытием EXE или Remove-AppxPackage: внешние файлы Sparse Package убираются отдельно. Удаление не затрагивает общие .NET/Windows App SDK runtime. Исходники и инструменты сборки принадлежат отдельному dev-контексту; dev-cleanup удаляет только созданные им артефакты по явной команде, не весь рабочий каталог.

## Проверка результата

1. Чистая Release-сборка и запуск исполняемого файла на этом компьютере.
2. Включение/выключение каждого типа, нескольких экземпляров, закрытие управления, работа трея и полный выход без оставшегося процесса.
3. Восстановление настроек после перезапуска; переподключение монитора и масштабирование DPI.
4. Настоящее воспроизведение из доступного приложения: смена трека, обложка, пауза, перемотка и неподдерживаемые команды. Не проверенные источники явно перечислить.
5. Погода: успех, недоступная сеть, некорректный город, сохранённые данные и повтор запроса. Текст песни: синхронный, обычный и отсутствующий.
6. Скриншоты окна и виджетов на светлом/тёмном фоне; клавиатура, контраст и уменьшение движения.
7. Замер CPU, памяти и поведения GPU в простое, при музыке, перемещении и со скрытыми виджетами; публикуются фактические результаты, без обещания «нулевой нагрузки».
8. Передача готовой сборки, исходников, краткой инструкции на русском и списка подтверждённых ограничений.
9. Отдельный ранний образец Liquid Glass до основной реализации: тестовая сетка, обои, перемещение, смена DPI, расход CPU/GPU и неподвижный режим. При провале меняется рендерер; Acrylic не выдаётся за успех.
10. Focus/Snooze: отмена всех запросов, отсутствие отложенных повторов, пауза тиков и анимаций, переход в глубокий сон и однократное корректное восстановление. Одноразовый timer и ручной возврат проверяются отдельно.
11. Уведомления: установленная сборка с identity, выдача/отказ/отзыв разрешения, пустые/длинные данные, разные приложения, отсутствие удаления оригиналов и отсутствие собственных всплытий в Snooze. Системные всплытия оцениваются отдельно и не объявляются подавленными listener-ом.
12. Быстрые настройки: фактические уровни громкости/mute и яркости, отсутствие поддержки монитора и отключение устройства. Изменение системных параметров в испытаниях только явными действиями; не гасить дисплей и не отключать сеть автоматически.
13. Win + D/Win + M, Explorer restart, сон/пробуждение, блокировка/разблокировка, полноэкранная игра, виртуальные столы; восстановление без изменения системных настроек. Проверка 100/125/150/200% DPI, отрицательных координат монитора и смены основного экрана; недоступные аппаратные сценарии явно обозначить непроверенными.
14. ИИ: провайдер не задан, неверный ключ, offline, таймаут, отмена, ограничение длины контекста, отсутствие доступа к экрану/уведомлениям и отсутствие фоновых запросов.
15. Установка → запуск → включение всех интеграций → «Отключить всё» → повторное включение → «Удалить полностью». Снимки принадлежащих приложению ресурсов до/после: процессы/окна, identity, автозапуск, ярлыки, локальные файлы/данные, credentials и созданные dev-регистрации. Финальный результат проверяется извне, повторный cleanup безопасен, перезагрузка не запускает приложение вновь.
16. Сбой на каждом этапе установки и удаления, заблокированный файл, отсутствие журнала/его повреждение, посторонний файл или junction внутри пути. Очистка не выходит за доверенные корни, не удаляет ресурсы с неопределённым владельцем, показывает остатки и позволяет повторить. Исходные фото, examples, Windhawk и чужие package registrations остаются нетронутыми.
17. IDesktopWallpaper: разные картинки на двух мониторах, Fill/Fit/Stretch/Center/Tile/Span, смена фона/slideshow, сплошной цвет и разные картинки активных виртуальных столов. Аппаратно недоступные случаи не объявляются проверенными.
18. Sparse Package: register → запуск EXE с проверкой identity → rebuild без повторного packaging → проверка listener permission → unregister → проверка отсутствия registration и внешних ресурсов. Включение Developer Mode/импорт сертификатов не являются скрытой частью сценария.
